# Multiple Failed Entra ID Sign-In Investigation

## Incident Summary

Microsoft Sentinel generated an incident after detecting repeated failed Microsoft Entra ID authentication attempts involving the lab account.

The detection was triggered by five or more failed authentication attempts associated with the same user and source IP address.

## Detection Source

The incident was generated by the Microsoft Sentinel Analytics Rule:

**Multiple Failed Entra ID Sign-Ins**

The rule monitors the `SigninLogs` table for authentication events with ResultType `50126`.

The rule runs every 5 minutes and evaluates the previous 10 minutes of authentication activity.

## Affected Entities

### User

`sentinellabuser`

### Source IP

The source IP associated with the failed authentication attempts was identified and mapped by Microsoft Sentinel as an IP entity.

## Investigation

The incident was investigated using Microsoft Sentinel's incident overview, alert details, entity information, investigation graph, and authentication data.

The investigation examined:

- Failed authentication attempts
- Successful authentication activity
- Authentication timestamps
- Source IP address
- User account
- Applications involved
- Authentication result codes
- Authentication timeline
- Related account activity

## Authentication Analysis

The authentication activity included repeated failed sign-in attempts associated with ResultType `50126`.

Additional authentication events were reviewed to determine whether successful authentication occurred following the failed attempts.

The investigation was used to establish the sequence of authentication activity and determine whether the behavior represented potential account compromise.

## Entity Correlation

Microsoft Sentinel successfully correlated the incident with:

- The affected user account
- The source IP address

The investigation graph provided a visual relationship between the security incident, user, and IP entity.

## MITRE ATT&CK Mapping

**T1110.001 — Password Guessing**

The activity was mapped to Password Guessing because repeated failed authentication attempts can be associated with attempts to discover or validate user credentials.

## Investigation Findings

The detection successfully identified repeated failed authentication activity against the lab account.

The activity generated a Sentinel alert and security incident, and the affected user and source IP were successfully identified as entities.

The authentication timeline was reviewed to determine whether the activity resulted in a successful authentication and whether additional investigation was required.

Because the authentication attempts were intentionally generated as part of this controlled security lab, the activity was determined to be simulated test activity rather than an actual account compromise.

## Recommended Production Response

If similar activity were identified in a production environment, a SOC analyst should:

1. Validate whether the authentication attempts were authorized.
2. Review the source IP address and geographic location.
3. Review successful authentication events following failed attempts.
4. Verify whether MFA was successfully completed.
5. Review additional activity associated with the affected account.
6. Reset the user's credentials if compromise is suspected.
7. Revoke active sessions when appropriate.
8. Continue monitoring the account and source IP for additional suspicious activity.

## Incident Disposition

The incident was classified as a true positive detection for the purposes of validating the security rule.

The activity itself was determined to be simulated test activity because the authentication attempts were intentionally generated during the lab.

The investigation findings were documented and the incident was closed after successful validation of the detection workflow.

## Lessons Learned

This investigation demonstrated the importance of correlating authentication events with users and source IP addresses.

The lab also demonstrated how Microsoft Sentinel can transform authentication telemetry into an actionable security incident that can be investigated and documented through a SOC workflow.

## SOC Workflow

The completed investigation followed this workflow:

**Detect → Alert → Investigate → Correlate → Document → Respond → Close**
